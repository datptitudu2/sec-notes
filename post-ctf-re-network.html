VSL CTF 2026 Writeup: Chaining LFI & Python SSTI (Key-Game & Trust-Issues)

VSL-CTF-2026 Web-Exploitation LFI SSTI

VSL CTF 2026 (hosted by VKU Security Lab on Jan 24–25, 2026) featured several neat web exploitation challenges that reward careful dependency auditing and sandbox-escape fundamentals. Below is a concise write-up of two challenges: Key-Game and Trust-Issues.

01. Key-Game — LFI via Legacy jQuery-jFeed Proxy

Auditing the challenge's Dockerfile revealed an outdated system package dependency: libjs-jquery-jfeed, which ships an unauthenticated example script at /javascript/jquery-jfeed/proxy.php.

  • Root Cause: proxy.php passes the user-supplied url parameter directly into a file/URL fetch without restricting schemes, allowing Local File Inclusion (LFI) via file://.
  • Secret & Session Extraction: Reading local files exposed the application's secret key and PHP session state:
    GET /javascript/jquery-jfeed/proxy.php?url=file:///var/www/secret_key.txt
    GET /javascript/jquery-jfeed/proxy.php?url=file:///tmp/sess_<SESSION_ID>
  • Exploit: Using the leaked secret key and session state, we forged/replayed valid session parameters to step through the 40-round validation loop automatically and retrieve the flag.

02. Trust-Issues — Python SSTI & Sandbox Escape

This challenge exposed a calculator endpoint (/calc?text=...) where untrusted input or poisoned HTTP headers reached a Python/Jinja evaluation context.

  • Root Cause: Insufficient input sanitization before template/expression evaluation, combined with header/log poisoning vectors.
  • Sandbox Escape Payload: Walking Python's object hierarchy from an empty tuple () to locate catch_warnings and access __builtins__['open']:
    [c for c in ().__class__.__base__.__subclasses__() if c.__name__ == 'catch_warnings'][0]()._module.__builtins__['open']('flag.txt').read()
  • Takeaway: Never overlook legacy OS packages in Dockerfiles (like libjs-jquery-jfeed) or expose Python object introspection in restricted evaluation contexts.
